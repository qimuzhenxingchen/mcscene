# COPY-GUARD：文案红线

这个 Skill 的核心价值不是"会写祝福语"，而是**写得出、也守得住**。以下每条都是硬约束，代码里对应 `scripts/mcsc_copyguard.py`，SKILL.md 里的 Agent 也必须遵守。

## 1. 不编造具体事实

禁止生成任何用户没提供过的具体事件、地点、时间、数字。

- ✗ "还记得去年我们在外滩那家店……"
- ✓ "不用想起哪一天，反正今天想吃点好的。"
- ✗ "你已经连续加班 37 天了"
- ✓ "最近挺累的吧。"

理由：AI 编出来的"共同记忆"是这类文案最容易翻车的地方，收的人一眼就能看穿。

## 2. 不做超出食物的承诺

本项目卖的是"一顿饭"，不是"关系的解决方案"。

- ✗ "这顿之后我们就和好吧"
- ✓ "上次是我没做好，这顿算我的。"
- ✗ "吃了这个就会开心起来"
- ✓ "先吃点热的。"

理由：活动规则明确禁止暗示食品具有疗效或非食品类功效。

## 3. 回避不健康饮食与浪费倾向

- ✗ "吃到扶墙出"、"热量刺客"、"报复性进食"、"暴食一顿"
- ✗ "多点几份，吃不完就扔"、"点满一桌才显得有诚意"
- ✓ "点得刚好，吃完不剩最好。"

## 4. 不做品牌对比与贬损

- ✗ 任何其他餐饮品牌名称
- ✗ "比某某家好吃多了"
- ✗ 对麦当劳产品、员工的负面、讽刺、调侃

## 5. 不碰敏感与人身边界

禁止：身材羞辱（胖/瘦/减肥失败）、年龄调侃、性别刻板印象、婚恋状况评价、收入/职业评价、地域刻板印象、政治与宗教内容、疾病与身体状况推断。

- ✗ "少吃点，你最近胖了"
- ✗ "三十了还没对象，先吃个堡吧"
- ✓ 只描述食物与心意，不评价人。

## 6. 价格与菜名只能来自 MCP 实时返回

- 禁止任何硬编码价格、凭空生成的菜品名、记忆里的旧价格。
- 报价与下单必须调用 `calculate-price`，并展示明细后等用户确认。
- 演示数据（`fixtures/`）必须打 `SIMULATED` 标记，不得伪装成实时结果。

## 7. 称呼不当

- 对上级、客户、不熟的人，禁止使用亲昵称呼（宝、亲爱的、老铁、兄弟）。
- 对长辈禁止使用网络流行语与颜文字堆叠。
- 未能确定关系时，默认使用中性称呼并提示用户确认。

## 8. 必须能一键换语气

同一份方案的文案必须能以至少 3 种语气重新生成（温润 / 损友 / 克制）。这是"真的能用"的底线——用户拿到一段不合适的文案，宁可不用。
